# Roadmap: Transcribator

## Цель проекта

Локальная утилита для транскрибации аудио и видео в текст. Результат сохраняется в txt и json (с таймкодами) для последующего анализа через AI-агента (рефлексия по созвонам, подсветки, аналитика).

## Отложено

- Английский язык
- Облачные API
- Запись с микрофона / URL
- **Диаризация через pyannote.audio на GPU** (лучшее качество): надёжно сама
  определяет число спикеров и обрабатывает перекрытия речи, считается на GPU за
  секунды. Блокер: у torch нет CUDA-колёс под Python 3.14. Путь — отдельный venv
  на **Python 3.12** (текущий 3.14 не трогать) + torch CUDA (~3 ГБ) + pyannote
  (нужен бесплатный HuggingFace-токен) + новый бэкенд диаризации. Альтернатива —
  дождаться cp314 CUDA-колёс PyTorch (срок неизвестен → заведётся в текущем venv).
  Начинать по явному запросу.
- Прогресс диаризации в GUI: CPU-проход (~7 мин на 94-мин файле) идёт без
  прогресс-бара (изолированный подпроцесс не шлёт прогресс в окно; лог пишет
  «идёт обработка»). Реальный прогресс потребует канал из подпроцесса в GUI.
- Надёжное авто-определение числа спикеров: текущий torch-free кластеризатор (sherpa FastClustering) завышает число на длинных файлах — нет универсального порога (число плывёт с длиной). Рабочий способ — задавать число спикеров вручную (дефолт 2). Возможное улучшение: своя оценка K по эмбеддингам (silhouette/eigengap) или pyannote на GPU-окружении.
- Повторная диаризация без повторной транскрибации: сейчас смена числа спикеров требует полного прогона (транскрибация заново ~10 мин). Если кэшировать транскрибацию (json со словами) и применять диаризацию отдельно, перебор числа спикеров для неизвестного N (5–7) станет дешёвым (~диаризация ~7 мин вместо полного прогона).
