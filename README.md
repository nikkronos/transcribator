# Transcribator

Локальная утилита для транскрибации аудио и видео в текст (русский). Результаты сохраняются в `.txt` и `.json` с таймкодами — удобно передавать в AI-агента для рефлексии по созвонам и аналитики.

- **Вход:** локальные файлы (аудио и видео), можно указать несколько за один запуск.
- **Выход:** для каждого файла создаются `имя_файла.txt` (весь текст) и `имя_файла.json` (сегменты с полями `start`, `end`, `text`).
- **Диаризация (опция):** «кто говорит» — реплики размечаются по спикерам (Спикер 1, Спикер 2…). В `.txt` текст группируется в читаемые реплики, в `.json` у каждого сегмента появляется поле `speaker`. Работает локально, без torch и без токенов (движок [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx), считается на CPU; модели скачиваются один раз и кэшируются).
- **Режим:** полностью локально (офлайн), язык — русский.

## Требования

- **Python 3.10+**
- **ffmpeg** — для извлечения аудио из видео (должен быть в PATH).
- Достаточно RAM и места на диске для модели Whisper (модель `small` — порядка 500 MB).
- **GPU NVIDIA (опционально):** для ускорения в GUI/CLI через CUDA на Windows обычно нужны pip-пакеты `nvidia-cublas-cu12` и `nvidia-cudnn-cu12` (~1.2 GB). Подробности — [docs/gui-and-gpu-windows.md](docs/gui-and-gpu-windows.md).
- **Диаризация (опционально):** пакет `sherpa-onnx` (ставится из `requirements.txt`). Считается на CPU и не требует GPU/torch. При первом использовании один раз скачиваются ONNX-модели (~34 МБ: pyannote-сегментация + 3D-Speaker CAM++) в `%LOCALAPPDATA%\Transcribator\models`.

## Установка

1. Клонируй репозиторий и перейди в папку проекта.

2. Создай виртуальное окружение и установи зависимости:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

3. Убедись, что **ffmpeg** установлен и доступен в PATH (для видео):

```powershell
ffmpeg -version
```

Если ffmpeg не установлен: скачай с [ffmpeg.org](https://ffmpeg.org/download.html) или через `winget install ffmpeg` (Windows) и добавь в PATH.

4. **Ускорение на GPU (Windows, NVIDIA):** при необходимости установи в том же `.venv`:

```powershell
pip install nvidia-cublas-cu12 nvidia-cudnn-cu12
```

При импорте пакета `transcribator` DLL из `site-packages\nvidia\...\bin` регистрируются автоматически (см. [docs/gui-and-gpu-windows.md](docs/gui-and-gpu-windows.md)).

## Использование

### Вариант 1: Окно для десктопа (удобнее)

Из корня проекта с активированным `.venv`:

```powershell
python -m transcribator.gui
```

Откроется окно: добавь файлы (аудио/видео), при необходимости укажи папку для результатов, **модель** и **устройство** (`auto` / `cuda` / `cpu`), при желании включи галочку **«Диаризация (кто говорит)»** и укажи **число спикеров** (для интервью/созвона — число участников; `0` = авто). Нажми «Запустить транскрибацию». Лог и **прогресс (процент, ETA, очередь)** — в том же окне.

> **Число спикеров — указывай его.** Авто-определение (`0`) на длинных записях ненадёжно: число «спикеров» завышается и плывёт с длиной файла (универсального порога нет — ограничение torch-free кластеризатора). Для надёжного результата укажи число участников. По умолчанию стоит `2` (типичный созвон/интервью); для двух ведущих + гостя — `3`, и т.д. Если не знаешь точно — начни с `2`.
>
> При включённой диаризации первый запуск один раз скачивает модели (~34 МБ) в `%LOCALAPPDATA%\Transcribator\models`. Диаризация считается на CPU **после** транскрибации; на длинном файле это несколько минут без отдельного прогресс-бара (в логе — «идёт обработка», это не зависание).
>
> Если файл уже обработан **без** диаризации, повторный запуск с галочкой переобработает его и добавит спикеров. Если результат уже **с** диаризацией — файл пропускается (удали `.txt`/`.json` или укажи другую папку, чтобы пересчитать).

Двойной щелчок по `Запуск Transcribator.bat` в корне проекта — то же окно через `pythonw` (без консоли). Если окно «тихо» закрылось, см. журнал: `%LOCALAPPDATA%\Transcribator\gui_crash.log` (подробнее в [docs/gui-and-gpu-windows.md](docs/gui-and-gpu-windows.md)).

### Вариант 2: Командная строка (CLI)

```powershell
# Один файл
python -m transcribator путь/к/аудио.mp3

# Несколько файлов
python -m transcribator файл1.mp3 файл2.mp4 запись.m4a

# Сохранить результаты в отдельную папку
python -m transcribator файл1.mp3 -o папка_результатов

# Другая модель (base — быстрее, medium — точнее)
python -m transcribator файл.mp3 -m base

# Диаризация с известным числом спикеров (рекомендуется — надёжно)
python -m transcribator созвон.mp3 --diarize --speakers 2

# Диаризация с авто-определением числа (на длинных файлах завышает)
python -m transcribator созвон.mp3 --diarize

# Подробный вывод
python -m transcribator файл.mp3 -v
```

Результаты по умолчанию создаются рядом с исходным файлом: `имя_файла.txt` и `имя_файла.json`. При указании `-o папка` оба файла пишутся в эту папку.

### Вариант 3: Telegram-бот (на сервере)

Перешли или отправь боту голосовое сообщение — он пришлёт текст (только русский, только текст в ответ). **Сейчас бот отключён** (не запущен); инструкции по включению/выключению — в [docs/bot.md](docs/bot.md).

- **Где живёт:** тот же репозиторий; бот предназначен для запуска на сервере (например, Timeweb).
- **Требования:** токен бота (создать через [@BotFather](https://t.me/BotFather)), на сервере — Python 3.10+, ffmpeg, достаточная RAM для модели.
- **Запуск:** задать переменную окружения `TRANSCRIBATOR_BOT_TOKEN` (или `BOT_TOKEN`), затем `python -m transcribator.bot`. Подробнее — в [docs/bot.md](docs/bot.md).

## Формат JSON

```json
{
  "source_file": "созвон.mp3",
  "language": "ru",
  "model": "small",
  "diarization": true,
  "num_speakers": 2,
  "segments": [
    { "start": 0.0, "end": 2.5, "text": "Привет, на связи.", "speaker": "Спикер 1" },
    { "start": 2.5, "end": 5.1, "text": "Давай обсудим план.", "speaker": "Спикер 2" }
  ]
}
```

Поля `diarization` (bool) и `num_speakers` (int) есть всегда; поле `speaker` у сегментов добавляется только при включённой диаризации. При диаризации сегменты режутся **по смене говорящего** (пословные таймкоды), поэтому каждый сегмент относится к одному спикеру — границы реплик точнее. Без диаризации `diarization: false`, `num_speakers: 0`, а сегменты содержат только `start`, `end`, `text` (обратная совместимость со старым форматом).
