# Резюме сессии 2026-06-18

## Задача

Доработать транскрибатор: (1) добавить диаризацию («кто говорит»), (2) сделать
результат читаемым, (3) оценить GigaAM как возможный движок. Разрешено
переделывать инфраструктуру при необходимости.

## Ключевые факты, найденные в начале

- **GPU работает.** Замер в текущем `.venv` (Python 3.14.5): faster-whisper на
  GPU ≈26× быстрее CPU (30с аудио: GPU **0.62с** против CPU **16.4с**). Гипотеза
  «медленно, потому что не на GPU» **не подтвердилась** — движок умеет в GPU.
- **Ограничение Python 3.14:** у PyTorch нет CUDA-колёс под 3.14 (только CPU,
  по состоянию на июнь 2026). Значит любой torch-зависимый путь (pyannote,
  WhisperX, **GigaAM**) на этом окружении пошёл бы на CPU и потерял GPU.
- **GigaAM** (MIT, заточен под русский) диаризацию не делает и требует torch →
  для задачи «кто говорит» не подходит; отложен как возможный A/B по точности.
- **faster-whisper** работает на `ctranslate2`, не на torch → остаётся на GPU,
  движок ASR не трогаем.

## Принятые решения

- **ASR:** оставить faster-whisper (GPU).
- **Диаризация:** `sherpa-onnx` — без torch и токенов, считается на CPU (лёгкая),
  модели бесплатные. Это самый чистый путь под Python 3.14 и нулевой бюджет.
- **Выход v1:** `.txt` со спикерами (читаемые реплики) + `.json` с полем
  `speaker`. Красивый HTML/MD-документ и веб-UI — заведены в ROADMAP.

## Выполнено

1. `transcribator/diarization.py` — диаризация на sherpa-onnx (pyannote
   segmentation 3.0 + NeMo TitaNet-small + fast clustering), авто-загрузка и
   кэш моделей (~46 МБ) в `%LOCALAPPDATA%\Transcribator\models`.
2. `audio_utils.ensure_wav_16k_mono(...)` — единый 16 кГц моно WAV для whisper и
   диаризатора.
3. `core.py` — параметры `diarize`/`num_speakers`/`diar_threshold` (в т.ч. через
   изолированный процесс), назначение спикера по перекрытию, читаемый `.txt`
   (`[mm:ss] Спикер N:`), `.json` с `diarization`/`num_speakers`/`speaker`,
   мягкий откат при сбое диаризации.
4. CLI: `--diarize`, `--speakers`, `--diar-threshold`. GUI: галочка
   «Диаризация (кто говорит)». `requirements.txt`: `sherpa-onnx`, `numpy`.
5. Документация: README, ROADMAP, DONE_LIST, agent-onboarding.

## Фикс по результатам реального теста (тот же день)

Никита прогнал реальное интервью (94 мин, 2 человека): авто-диаризация дала
~53 «спикера», ощущалось как зависание.

- **Диагностика тестом** (5-мин клип того же файла, без повторной транскрибации):
  пороги кластеризации и три эмбеддинг-модели. Вывод: **авто-режим завышает у
  всех** (лучший — 6 спикеров на 2 человека), **фикс. число спикеров = ровно 2**.
- **Решения:** эмбеддинг TitaNet → **3D-Speaker CAM++** (быстрее, не хуже); в GUI
  поле **«Число спикеров (0 = авто)»**, дефолт 2; порог авто 0.5 → 0.7; потоки
  диаризации 2 → до 8; честный лог про CPU-диаризацию (не зависание); умный
  пропуск (старый результат без диаризации переобрабатывается).
- **Проверка:** e2e на 5-мин клипе с `--speakers 2` — чистое чередование 2
  спикеров, совпадает с Q&A-логикой интервью.

## Word-level слияние (точность атрибуции)

Грубое слияние «один спикер на сегмент whisper» путало границы. Решение как в
WhisperX: при диаризации включаются пословные таймкоды, спикер назначается на
каждое слово, сегмент режется в точке смены говорящего (`core._segments_by_speaker`,
`diarization.speaker_label`). Юнит-тест разбиения пройден; полный 94-мин файл
прогнан реальным пайплайном со `speakers=2`.

Время на 94-мин файле: транскрибация на GPU быстрая; диаризация на CPU ~7 мин
(8 потоков, CAM++). Авто-определение числа спикеров ненадёжно — число задаётся.

Word-level в местах перебивания (crosstalk) давал обрывки 1-2 слова — добавлено
сглаживание `core._smooth_short_turns` (короткая <1с реплика поглощается длинным
соседом; на реальном файле 1015 → 173 реплики, чтение чистое).

**Нюанс ctranslate2:** на Windows+CUDA процесс может падать exit 127 на выгрузке
модели — ПОСЛЕ записи файлов (безвредно). GUI это переживает: изолированный
подпроцесс + приём результата при валидных файлах (`_outputs_look_valid`).

## Итог по диаризации

Рабочий читаемый транскрипт 2 спикеров. Время на 94-мин: транскрибация со
словами ~3 мин (GPU) + диаризация ~6-7 мин (CPU) = ~10 мин. Остаточные огрехи
атрибуции (перекрытия речи) — предел torch-free CPU-диаризации; полный фикс =
pyannote на GPU-окружении (отложено).
